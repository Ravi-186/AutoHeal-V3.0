# AutoHeal Phase 8: Database Schema Enhancements

## 1. Overview

Phase 8 introduces two new persistent tables to the AutoHeal SQLite database (`autoheal/shopsphere/database.py`), expanding the total platform schema to **26 production tables**:
- **Table 25**: `soc_copilot_conversations` — Multi-turn conversation sessions, analyst dialogues, and structured findings.
- **Table 26**: `incident_reports` — 12-section formal post-incident investigation reports with cryptographic audit hashes.

---

## 2. Table 25: `soc_copilot_conversations`

### 2.1 Purpose & Role
Provides persistent conversation history for SOC analyst investigations. Supports multi-turn context retention, analyst attribution, and telemetry linking across browser reloads.

### 2.2 DDL Specification
```sql
CREATE TABLE IF NOT EXISTS soc_copilot_conversations (
    session_id TEXT PRIMARY KEY,
    analyst_id TEXT NOT NULL,
    incident_id TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    title TEXT DEFAULT 'Untitled Investigation',
    status TEXT DEFAULT 'ACTIVE', -- ACTIVE, CLOSED, ARCHIVED
    messages_json TEXT DEFAULT '[]', -- Array of {role, content, timestamp, citations}
    metadata_json TEXT DEFAULT '{}',
    FOREIGN KEY(incident_id) REFERENCES security_incidents(incident_id)
);

CREATE INDEX IF NOT EXISTS idx_copilot_conv_analyst ON soc_copilot_conversations(analyst_id);
CREATE INDEX IF NOT EXISTS idx_copilot_conv_incident ON soc_copilot_conversations(incident_id);
```

### 2.3 Column Details
- `session_id`: Primary key string formatted as `SESS-YYYYMMDD-XXXX` or custom analyst identifier.
- `analyst_id`: Identifier of the SOC analyst or operator initiating the session.
- `incident_id`: Optional foreign key linking the conversation to a specific `security_incidents` record.
- `messages_json`: Serialized JSON array storing conversation messages (`role`: `analyst` | `copilot` | `system`).
- `metadata_json`: Additional context such as active filter states or pinned evidence IDs.

## 3. Table 26: `incident_reports`

### 3.1 Purpose & Role
Stores formal executive and technical incident reports generated by the Copilot or human analysts. Facilitates compliance reporting (SOC 2 Type II, ISO 27001, PCI-DSS) and provides an immutable audit trail.

### 3.2 DDL Specification
```sql
CREATE TABLE IF NOT EXISTS incident_reports (
    report_id TEXT PRIMARY KEY,
    incident_id TEXT NOT NULL,
    generated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    author TEXT DEFAULT 'AutoHeal AI SOC Copilot',
    title TEXT NOT NULL,
    status TEXT DEFAULT 'DRAFT', -- DRAFT, REVIEWED, APPROVED, ARCHIVED
    executive_summary TEXT NOT NULL,
    report_data_json TEXT NOT NULL, -- Complete 12-section structured report JSON
    compliance_tags_json TEXT DEFAULT '["SOC2","PCI-DSS","ISO27001"]',
    sign_off_analyst TEXT,
    sign_off_timestamp TIMESTAMP,
    audit_hash TEXT NOT NULL,
    FOREIGN KEY(incident_id) REFERENCES security_incidents(incident_id)
);

CREATE INDEX IF NOT EXISTS idx_reports_incident ON incident_reports(incident_id);
CREATE INDEX IF NOT EXISTS idx_reports_status ON incident_reports(status);
```

### 3.3 Column Details
- `report_id`: Unique identifier formatted as `REP-YYYYMMDD-XXXX` (e.g., `REP-20261101-INJ1004`).
- `incident_id`: Foreign key pointing to the target `security_incidents` record.
- `report_data_json`: Serialized JSON containing all 12 formal report sections.
- `audit_hash`: Cryptographic SHA-256 hash calculated over the report content and raw incident telemetry at generation time.
- `sign_off_analyst`: Name/ID of the human analyst who reviewed and approved the report.
